# Массовый импорт задач

Этот файл описывает рабочий процесс для архивов вроде турнира Колмогорова,
IMO и IMO Shortlist.

## Журнал импорта

Каждый проход по источнику фиксируется в `data/import_batches/*.yaml`.
Журнал не является карточкой задачи. Он отвечает на вопросы:

- какие источники были просмотрены;
- какие задачи стали кандидатами;
- что уже добавлено в базу;
- что оказалось дубликатом;
- что пропущено и почему;
- какие задачи требуют ручной проверки.

Статусы элементов:

- `candidate` — найден кандидат, карточка ещё не создана;
- `added` — карточка создана, поле `problem_id` обязательно;
- `duplicate` — это уже существующая карточка или переформулировка;
- `skipped` — задача не подходит базе;
- `needs_review` / `needs_human_review` — не хватает уверенности.

## Профиль задачи

У новых карточек желательно заполнять `problem_profile`. Это навигационный слой,
который помогает искать родственные задачи, когда одних меток уже мало.

Рекомендуемые поля:

- `objects`: основные объекты, например `grid`, `bipartite_graph`, `tournament`;
- `methods`: методы решения, например `double_counting`, `longest_path`;
- `transformations`: переходы, например `complement_graph`, `auxiliary_graph`;
- `goal`: тип цели, например `existence`, `minimum_attempts`, `edge_bound`;
- `auxiliary_graph_type`: если граф появляется только в решении;
- `invariants`: чётность, связность, степень, раскраска и т.п.;
- `keywords`: короткие свободные ключи для поиска;
- `status`: статус проверки профиля.

Профиль не заменяет `tags` и `standard_idea_ids`. Он нужен для более тонкого
поиска связей: например, две задачи могут обе использовать лес, но в одной лес
является условием, а в другой возникает как граф сравнений в решении.

## Добавление задач из архива

1. Создать или обновить import batch.
2. Для каждой найденной задачи проверить официальный или устойчивый источник.
3. Проверить дубликаты:
   `python tools/search.py query "ключевые слова задачи"`
4. Создать карточку только для опубликованной задачи с решением.
5. Заполнить оригинальную формулировку и графовую формулировку, если она
   является самостоятельной и эквивалентной.
6. Заполнить `problem_profile`, `tags`, `standard_idea_ids`.
7. Запустить:
   `python tools/suggest_relations.py --problem <id>`
8. Добавить только те связи, для которых есть содержательный текст.
9. Обновить import batch: `added`, `duplicate`, `skipped` или `needs_review`.
10. Запустить `validate`, `check_links`, `build_index`, `build_viewer`.

## Раздельные связи

Основной файл `data/relations/relations.yaml` остаётся рабочим.
Для больших новых проходов можно складывать связи в
`data/relations/relations.d/<batch-or-topic>.yaml`.
Инструменты читают оба места и проверяют уникальность `id`.
